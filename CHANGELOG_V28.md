## CRITICAL FIX

### 1. Broken `onerror` image-fallback handler (`app.js`, `article.html`, `bookmarks.html`)

**Bug:** `buildNewsCard()`, `buildHeroCard()` (in `static/js/app.js`), and the
duplicated card-building code in `static/article.html` and
`static/bookmarks.html` all built their `onerror="..."` fallback using a
backslash-escaped quote inside a JS template literal:

```js
onerror="this.parentElement.innerHTML='<div class=\"news-image-ph\">...'"
```

`\"` is a JS string escape — it is resolved to a literal `"` *before* the
markup ever reaches the HTML parser. By the time this string was inserted via
`innerHTML`, the attribute looked like `onerror="...class="..."` to the
browser: an unescaped quote that prematurely closes the `onerror` attribute.
Whenever an article image actually failed to load (broken source URL, expired
hotlink, offline image host — a routine occurrence for a news aggregator),
the browser tried to compile the truncated, now-invalid remainder as the
handler body and threw `SyntaxError: Invalid or unexpected token` in the
console. The placeholder icon never rendered — visitors saw a broken-image
icon instead of the intended 📰 fallback.

Confirmed via a real headless-browser test (Playwright + Chromium): with a
test article pointing at an unreachable image host, every card threw this
error on load; after the fix, zero errors on the same page.

**Fix:** replaced the escaped quote with the HTML entity `&quot;`, which
survives JS template-literal evaluation intact and is correctly decoded by
the HTML parser *within* the attribute value instead of ending it early:

```js
onerror="this.parentElement.innerHTML='<div class=&quot;news-image-ph&quot;>...'"
```

Fixed in all four locations: `buildNewsCard()`, `buildHeroCard()`
(`static/js/app.js`), the article-image handler in `static/article.html`,
and the duplicated card builder in `static/bookmarks.html`. `app.min.js` /
`style.min.css` regenerated from source afterward.

## MEDIUM FIX

### 3. `trends.html` linked a stale minified stylesheet

**Bug:** every page loads `css/style.css` directly except `trends.html`,
which linked `/static/css/style.min.css` — a build artifact that only gets
regenerated by manually running `scripts/minify.py`. Any edit to
`style.css` that wasn't followed by that build step would silently leave
`trends.html` out of sync with the rest of the site.

**Fix:** pointed `trends.html` at `/static/css/style.css`, matching every
other page. Also reran `scripts/minify.py` so `style.min.css`/`app.min.js`
are in sync with current source, in case a future page references them.

## LOW — PRODUCTION-READINESS FIX

### 6. No real 404 response for unmatched URLs

**Bug:** the catch-all frontend route (`main.py`, `serve()`) fell back to
serving `index.html` for *any* unmatched path — with an implicit `200`
status. A broken link, an old bookmarked URL, or a typo would silently
render the homepage as if it were a valid, distinct page. Search engines
indexing a `200` for a broken URL is a real SEO soft-404 problem, and it's
confusing for anyone who lands on a dead link.

**Fix:** added `static/404.html`, built from the site's own `.error-page` /
`.error-code` / `.error-btn` CSS classes — which already existed in
`style.css` but were never actually used anywhere. The catch-all route now
returns this page with a genuine `404` status code for any path that isn't
a real file, while every legitimate page/asset still resolves exactly as
before (verified with a fresh-boot smoke test across all 14 pages).
